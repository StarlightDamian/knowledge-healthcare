## 数据与内容归属

| 内容 | 唯一正文位置 | 引用方式 |
|---|---|---|
| 已有疾病、症状的概览、诊疗、药物、护理等 14 维度 | `data/conditions/{id}.json` | 知识条目的 `condition_ids` |
| 癌症总论与登记主题 | `data/knowledge/cancer.json` 的 `sections`、`entries` | 模块内按条目 ID 读取 |

一个知识条目只有一个 `group_id`，条目 ID 在两个知识模块之间唯一。主归档负责导航，风险因素、病症关联与生命阶段负责交叉引用。这里的 MECE 约束是单一归档和不重复计数，不要求生物学上的影响彼此独立。

例如，癌症模块的乳腺和结直肠条目可分别引用 `breast-cancer`、`colorectal-cancer` 病症；血压、血糖和脂肪分布因素可引用 `hypertension`、`type-2-diabetes`、`obesity`。链接表示相关知识入口，不表示“一个风险因素就是一种疾病”，也不创建同名病症副本。引用的条件是对应病症 ID 实际存在。

## 来源定位与审核状态

核查路径为“模块/条目/阶段 → 章节 `source_ids` → 本模块来源的 URL 与 `scope`”。来源登记包括 `id`、标题、HTTPS URL、`accessed_at` 和支持范围；核查者在 `scope` 或相应核查记录中说明实际读到的标题、表格、版本及适用人群。章节引用选择真正支持该章节的来源，不把整篇来源无差别复制到所有章节。

结构验证检查来源 ID 和 HTTPS、日期、双语完整、唯一归属以及引用作用域：条目来源属于本模块，条目章节来源属于该条目；总论和阶段章节来源属于本模块。原有病症的 `source_ids` 继续使用原证据登记，不为跨入口阅读而复制或改写原有来源记录。

模块 `review.status=editorial` 与病症审核状态分别记录，`updated_at` 是编辑日期。已打开官方页面、完成来源定位、通过结构测试分别是可追溯的编辑证据；医学主张核验、翻译审核和临床签审仍是独立工作。当前门禁只接受知识模块的 editorial 状态，并阻止其进入 clinical 构建；改成已审标签不会获得发布资格。

## 统计与验收口径

`stats.knowledge` 汇总两个模块及各模块的条目、章节、来源和阶段数量。36 个癌症登记主题、20 个健康因素与 7 个阶段视图分别计数；年龄分区只有 6 个，孕产视图是叠加层。

现有病症保持 72 条，仍使用 14 维度正文、病症目录及 22 列 CSV。新增总论、登记组、因素、阶段和交叉链接均不加入病症数、病症来源数或 ICD 覆盖分子。ICD-11 MMS 2026-01 的完整冻结目录和逐类映射仍按[覆盖审计与补充计划](coverage-audit-and-roadmap.md)独立推进。

本映射的验收检查为：34+2 癌症条目和 20 个因素有明确归属；病症引用均存在；所有因素引用指向同一规范条目；六年龄段完整无交叉，孕产为 overlay；章节来源在正确作用域内；模块审核状态与医学发布门禁一致；构建可将新数据嵌入单文件且不改变既有病症导出契约。原始报告没有细化到的病理实体、逐主张核验和地区化建议，按后续内容工作记录，不通过增加标题数充当完成。

# 面向初次阅读者的正文标准

本标准适用于现有72篇及后续新增病症。内容面向公众理解疾病与就医过程，不是个体诊断、处方或急救资质培训。

## 怎样写才算解释清楚

每节先用一句导读说明本节解决什么问题，再用独立要点解释。需要时补充原因、具体例子、操作方式和适用边界。专业术语首次出现即解释，避免用“高危”“个体化”“对症”“遵医嘱”代替正文。每条只讲一个主要问题，条数由知识决定，不用通用句子凑数。

| 维度 | 必须回答的问题 |
|---|---|
| 病症概览 | 是什么、影响哪里、有哪些典型表现、为什么会影响生活？首段用于卡片，其余为完整介绍。 |
| 病因与危险因素 | 已知病因、诱因、提高发生可能性的因素如何区分？哪些可改变？ |
| 危险信号 | 普通人可识别的严重表现是什么，出现后应怎样行动？放在详情正文之前。 |
| 何时就医 | 急救、尽快就诊、常规复诊、适合观察的情况分别是什么？何种变化要升级处理？ |
| 诊断方式与局限 | 医生问什么、检查什么、每项检查为了什么，哪些结果不能单独确诊或排除？ |
| 相似问题 | 为什么相似、医生怎样区分、哪些危险情况需优先排除？不能让读者仅凭表格自行排除。 |
| 常见治疗与目标 | 处理病因、减轻症状、控制病情、减少长期损伤各对应什么措施和条件？ |
| 药物角色与风险 | 类别和代表药有什么作用、不能做到什么、有哪些关键风险与监测要求？不提供个体剂量。 |
| 饮食 | 有哪些疾病相关的可执行例子？哪些人需要限制？什么证据不足、不能替代治疗？ |
| 日常护理 | 怎样实施、观察和记录，避免什么，何时停止自行处理？ |
| 特殊人群 | 哪些人群确实有不同的表现、评估或处理要求，为什么？ |
| 病程与随访 | 通常怎样变化、哪些因素影响恢复或复发、复查关注什么？ |
| 并发症 | 名称是什么意思、与原病症有何关系、有什么需要再次评估的变化？不把少见风险说成必然。 |
| 预防 | 如何减少首次发生、复发、恶化，哪些不能完全预防，筛查和预防有何区别？ |

症状入口（胸痛、发热等）必须说明可来自不同疾病。饮食、治疗和药物按原因介绍，不给所有胸痛套用同一种治疗。资料没有疾病特异饮食时解释边界，不编造食谱。

## 双语与证据

中文、英文必须保留相同的主要知识、数字、紧急程度和适用条件，不能只翻译中文的第一句话。其他界面语言明确回退英文。地区不同的诊断门槛、药品许可或就医路径应注明来源地区，不直接外推。

各节 `source_ids` 指向实际支持本节的资料；整篇 `source_ids` 还保留原有候选资料登记，不表示每一候选来源均在此次重新核验。实际阅读章节、来源定位、不可访问页面及不确定性记录在 `reports/content-expansion/batch-*.json`。

正文保留真实编辑与签审状态。完成逐主张来源核验及独立对抗审核的章节可标记 `verified`，对应证据记录见 `data/evidence/editorial-checks/`；未完成者保留待核验状态。编辑核验不等于执业医生签审，也不自动提升医学或翻译签审。药物风险、急症、儿童及孕产内容按实际条件核对。

## 数据与维护

`sections.<field>.text` 中的中英字符串是唯一正文。空行分段，`- ` 行为列表；不支持 HTML 或可执行 Markdown。摘要首段自动用于卡片，详情与CSV使用全文，比较表显式展开全文。修改正文会改变既有内容哈希，使旧签审不再适用。

`python -m src.guide content-audit` 生成可复算的结构、来源定位及正文哈希汇总。字数、列表存在和14栏非空只能发现缺漏，不能证明医学准确或读者理解。人工对抗检查关注：术语未解释、通用模板复制、来源不支持、双语遗漏、症状页强套治疗和夸大风险。

## 与病种覆盖的关系

72篇全部扩写只解决已收录主题的深度。全病种覆盖还需要冻结ICD目录、逐类别映射和逐篇内容判定；不能把文字增长、标题数量或结构测试通过当作95%覆盖。见 [覆盖审计与补充计划](coverage-audit-and-roadmap.md)。

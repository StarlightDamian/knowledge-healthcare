# 添加一个主题，不修改业务代码

从根目录运行 `python -m src.guide new stable-slug --zh "中文名称" --en "English name"`。输出在 `drafts/`，不会自动进入搜索。完整模板也在 `templates/condition.json`。

先填写一个主目录、条目类型、双语名称/别名/症状词、稳定科室 ID、14 个正文段落和局限说明。没有充分证据的高级字段保持 null；不得把“未知”写成“无风险”。新增名称不能改变既有 ID，避免破坏引用和比较。

在 `data/evidence/sources.json` 增加真实来源记录，确定网页究竟是正文、目录、摘要还是仅标题，并核实主题相关性。给各段挂接支持它的候选来源；不能因另一段引用过该来源就默认适用。保留 `support_status=pending_claim_verification`，除非真的完成规定签审。

已填写草稿移入 `data/conditions/` 后运行 `python -m src.guide validate`。因当前主程序只索引这里，新增主题会自动进入分类、搜索、详情、比较、CSV 与轻量目录。再运行构建与测试。测试中当前计数72是本版本回归基线，扩大内容时需要审核后更新计数断言，不应删除断言。

以 PR 提交，说明来源、检索范围、证据冲突、地区、人群、机器辅助使用情况和未完成事项。请勿上传真实患者姓名、联系方式、病历截图等敏感信息。测试病例必须为合成/充分授权去标识化资料且来源明确，不能将合成题改名为代表性样本。

临床发布另需医生/药师资质核验、内容/来源哈希绑定签审、翻译签审和地区验证。不要自己把 `credential_verified`、`medically_reviewed`、`clinically_validated` 从 false 改为 true 就声称审核完成。

新增语言先补齐 UI 键并运行测试；医学正文和临床地区需要独立流程。新增主目录、紧急规则或内容字段属于架构变化，需要同时调整 Schema、展示、导出、门禁和回归测试。

# 开放医学指南：双向钢人论证与实施决策

版本：0.1.0-preview；研究与编辑日期：2026-09-29。

## 1. 用最强的形式重新定义问题

你真正需要的不是一份“列出很多疾病的百科”，也不是把生活建议站换成医疗术语。目标应当是：把分散、更新速度不同、适用人群不同的医学资料，变成公众能快速查阅、研究者能横向比较、医生能审查、贡献者能增补、程序和 Agent 能局部读取的开放知识基础设施。

对用户，它回答：我在查什么？哪些表现不能等？通常从哪个医疗入口开始？哪些检查和治疗是常见路径？哪些做法缺乏充分依据？资料适用于哪些人和地区？我们确定什么，又不确定什么？

对维护者，它回答：这句话来自哪里？两个来源是否独立？是否真支持同一主张？全文还是摘要？是谁、什么时候、依据哪个版本审核？原文变化后，哪些条目失效？翻译是否改变了临床意义？

因此目标是六个相互制约的系统：内容、证据、检索、危险提示、本地化、治理。网页只是它们的展示层。“正确”应表现为可检查的证据链和错误处理，不应成为未经验证的产品标签。

## 2. 支持当前构想的最强论证

### 2.1 标准化可以创造官方网页本身没有提供的使用价值

不同机构的资料组织方法不同，公众为了比较两种相关疾病，需要反复寻找症状、检查、治疗和就医节点。把这些维度统一起来，可以让“相同的问题得到相同位置的回答”，并显式显示缺失项，而不是把缺失误当成没有风险。这是信息组织的价值，并不要求本项目重新发现医学。

### 2.2 开源适合暴露错误、追踪改动和降低重复劳动

稳定 ID、结构化字段、来源关系、Git diff、变更影响图和可重复构建，让第三方可以指出具体错误，并使纠正传播到网页、比较表及数据接口。静态网页把软件运行成本压低；不必先建设账号、支付、数据库和云端推理服务。两个参考项目展示了静态内容、检索和单文件离线分发的可行做法。[R1][R2]

这并不证明“开源即可信”。真正的支持论点是：相较于黑箱答案，开放证据链为发现和修复问题提供了条件。

### 2.3 最小化查询上传可以成为产品优势

本实现不需要把症状发往模型服务。界面检索在浏览器本地完成，也不写入 localStorage 或查询 URL。这是已经实现的架构选择，减少了处理敏感查询的外部系统数量；它不意味着托管商没有访问日志，更不等于获得任何隐私法规认证。

### 2.4 严格缩小承诺后，项目依然实用

不输出诊断概率，不代表不能帮人找到相关资料。名称、俗称和症状词检索、疾病对比、证据透明、危险信号和就医入口介绍，已经构成完整的阅读导航任务。将这些内容做对，比直接建设未经验证的个体诊断器更符合第一阶段的资源配置。

## 3. 反对当前构想的最强论证

### 3.1 最好的替代方案可能是维护权威资料目录，而不是重写百科

NHS、WHO、CDC、NICE 和 NIH 机构已经持续维护大量资料。如果新项目仅把它们重新摘要、翻译，再增加一个搜索框，却没有稳定医学编辑团队，可能只是额外制造一个更易过期的副本。每一次改写都可能丢掉适用条件；每增加一种语言，又增加一条错误传播链。

因此本项目必须证明“统一比较、字段证据、局部读取、更新影响追踪”等增量价值，不能用页面漂亮或条目数量取代医学维护能力。

### 3.2 简短搜索会诱导用户把相关性当成病因解释

“咳嗽、发热、乏力”等词不能包含完整病史、生命体征和查体信息。排名第一的主题很容易被理解为最可能诊断，而排序分数并不是校准后的疾病概率。错误后果并不对称：漏掉危重情形，与多推荐一个无关主题，不是同等级错误。

2015 年 BMJ 的原始审计研究在当时测试的症状检查器中发现诊断和分流不足。[R3] 这是历史研究，不可拿其百分比推断所有 2026 年产品的表现；它支持的设计结论是“必须独立评估本系统”，而不是“所有症状工具永远无效”。本仓库没有这样的临床验证结果。

### 3.3 多条链接可能制造比没有引用更强的虚假信任

两个网页可能引用同一项研究，也可能分别支持同一句话的不同部分。来源的机构声誉、期刊品牌和 DOI 不能替代研究设计、偏倚、直接性、人群及效果与伤害的判断。WHO 的指南方法强调系统检索、证据综合、质量评价、利益冲突和透明决策。[R4]

“每条有两个来源”在本项目只是初步治理规则，不是 WHO 规定的充分证据标准。真正交叉审核必须把主张拆小，记录支持位置，并判断一致性和适用边界。当前 1,008 个完整正文段落没有完成这个过程，不应把候选引用写成已签审证据。

### 3.4 全球化不只是翻译量的乘法

英语也可以对应不同临床地区。药品许可、处方规则、就医入口、可用检查、儿童阈值和地方指南可能不同。把英国的路径直接翻译成中文，并不会自动成为中国版本。当前 `clinical_region=UNSPECIFIED`，12 种界面语言中仅有两种正文，其余有明确回退；不能宣传为 12 国医学指南。

### 3.5 用途越界会改变工程与治理要求

FDA 2026 年 CDS 指南围绕软件功能和适用情形区分器械与非器械功能，也明确涉及面向患者和照护者的软件。[R5] 本文不判断本项目在某司法辖区的最终属性。它说明：开源、免费或写免责声明，都不能自行完成监管判断。增加个体化诊断或治疗输出之前，必须重新开展目的、风险、验证及地区合规评估。

## 4. 双方真正的分歧

| 变量 | 使低风险知识导航更成立 | 会显著改变方案的情况 |
|---|---|---|
| 产品承诺 | 查资料、比资料、理解常见路径 | 直接判断个人疾病、治疗或能否等待 |
| 首发人群/地区 | 明確的人群和临床地区 | 同时覆盖所有年龄、妊娠和全球地区 |
| 覆盖率分母 | 独立裁定的代表性真实需求 | 用 ICD 数量、页面数或自造题目代表 95% |
| 医学维护能力 | 有资质核验、双审和复核预算 | 软件团队自行给自己贴医学审核标签 |
| 可接受错误 | 可解释的资料漏召回并持续改进 | 危急漏分流又无独立临床安全验证 |
| 多语言策略 | 界面先行，正文/地区逐项签审 | 自动翻译即发布临床推荐 |
| 可持续性 | 来源更新能追踪到具体主张 | 靠一次性批量生成后长期无人维护 |

关键并非“条目要 72、500 还是 1,000”，而是适用范围、审核能力、验证分母和输出是否直接支配个人医疗决策。改变其中任一个条件，都可能改变项目投入和发布门槛。

## 5. 本次采用的决策

采用“可追溯健康知识导航 + 静态优先 + 编辑预览”，不把它称为已经临床验证的诊断平台。软件功能实做，知识库范围实报，未完成的证据字段保持待核验或空值。

72 个条目不只包含轻症，也有卒中、严重过敏、胸痛、妊娠相关紧急问题等安全相关主题。这是选题上的风险考虑，不是已经完成安全覆盖的证明。198 个待办标题独立存储，不充当内容数量。

“全部病例横向比对”本版明确落实为“全部已编写疾病/健康主题的统一字段对比”。它不是患者病例管理、诊断推断或病历相似度系统；真实病历涉及另外的数据、授权、隐私和验证任务。

## 6. 95% 如何真正验收

先约定地区、人群、场景和采样方法，再收集去标识化的实际信息需求，由独立人员裁定查询对应的主题与最低可用内容。计算有权重的“高质量条目覆盖需求数 / 所有抽样需求数”，并公开未知、无匹配和被排除项。

区分：标题映射率、检索召回率、医学已审核信息覆盖率、临床安全表现。它们不能合并成一个“准确率”。儿童、妊娠、高龄及危重场景应分层报告；抽样设计和置信区间必须与数据相适应。合成回归题只能证明代码按预设运行，不能建立人口覆盖率。

本版提供 CSV 计算器和校验，但没有代表性样本，`daily_need_coverage=null`。这不是用低数字代替高数字，而是承认尚无合法的统计分母。

## 7. 下一次能称为“医学已审版本”的必要变化

至少需要逐主张证据抽取与冲突处理；独立医生/药师审核及可验证资质；指定地区的正文与术语本地化；独立、冻结、可重跑的危险场景和误分流评估；更新/撤稿/安全通知处理；部署地区用途合规判断。实际人数、费用、周期取决于选定范围，本文不把猜测写成承诺。

软件门禁检查这些材料的记录和哈希绑定，不验证现实中审核者是否诚实，也不替代临床试验或监管认证。需要受保护的分支、真实人员和责任制度共同生效。
